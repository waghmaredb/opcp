# OPCP 90-Day Launch Plan

## Objective

Prove that OPCP can become the neutral AI control layer for mid-tier banks, NBFCs and digital banks by completing one real process, one real supplier swap and one credible design-partner pilot.

## Phase 1 — Days 0–14: sharpen the wedge

**Engineering**
- freeze the first process-pack shape;
- wire SME credit origination into the reference runtime;
- create two deterministic supplier adapters for one R0 capability;
- add swap-drill evidence output;
- add a minimal adoption dashboard view.

**Product**
- define the buyer journey from Exit Readiness -> Swap Drill -> Control Plane;
- define the AI Replaceability Index;
- write the five-minute demo script.

**Market**
- identify 10 target institutions in Singapore and India;
- secure 3 design-partner conversations;
- validate that exitability and AI supplier concentration are budget-worthy problems.

**Gate:** at least one design partner agrees to use the scorecard on a real critical process.

## Phase 2 — Days 15–45: prove the swap

**Engineering**
- execute a shadow swap drill;
- compare the same test set across two suppliers;
- enforce context lease equivalence;
- enforce authority-policy equivalence;
- produce exportable evidence;
- make promotion a configuration-only operation.

**Product**
- build the adoption control center around processes, capabilities, suppliers and swap readiness;
- make the swap drill the primary interaction;
- add sponsor readout.

**Market**
- run scorecard pilots with 3–5 institutions;
- choose one process with real supplier dependency;
- obtain sponsor-level feedback.

**Gate:** first measured time-to-swap on a critical capability.

## Phase 3 — Days 46–90: convert proof into a platform

**Engineering**
- publish the first process pack;
- publish the first two certified supplier adapters;
- add a conformance test suite for the chosen capability;
- harden exports and offline operation;
- add process/capability versioning.

**Product**
- package Exit Readiness as the commercial wedge;
- package Swap Drill as the proof product;
- package Control Plane support as the expansion product;
- define supplier certification.

**Market**
- convert 1–2 pilots into paid design partnerships;
- secure the first reference customer;
- recruit the second supplier for each capability where possible;
- begin ASEAN expansion conversations.

**Gate:** at least one customer has a proven exit and is willing to reference the result.

## Weekly operating cadence

Every week answer five questions:

1. What critical process did we make more replaceable?
2. What supplier can now be swapped that could not be swapped last week?
3. What evidence can a bank show its regulator, board or procurement team?
4. What customer behavior changed because of OPCP?
5. What assumption did we invalidate?

## Kill criteria

Do not expand the platform if:

- banks do not recognize supplier lock-in as a material AI adoption barrier;
- customers will not provide a real process for a scorecard or drill;
- a second supplier cannot implement the same capability contract;
- the swap drill cannot demonstrate measurable value;
- customers prefer a vendor-specific platform even when portability is demonstrated.

## North-star progression

```text
Processes assessed
      -> Processes with fallbacks
      -> Processes with swap drills
      -> Processes with proven time-to-swap
      -> Processes running interchangeable AI capabilities
```

The last number is the long-term measure of whether OPCP is becoming infrastructure.
